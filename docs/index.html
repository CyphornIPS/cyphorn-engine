CyphornIPS Documentation

A transparent, inline Intrusion Prevention System and Network Security Monitoring engine for Linux gateways and edge firewalls. CyphornIPS performs stateful inspection, protocol DPI, file inspection, threat intelligence matching, policy enforcement and atomic hot reload.

Operational warning: v1.5.0 is an experimental Developer Preview / Alpha release intended for evaluation, security research, lab validation and community testing. It is not certified as a sole, unmonitored security perimeter for mission-critical production environments.

🚀 Installation

Supported platform

Debian / Ubuntu · Linux · x86_64 / amd64

Recommended method

Install the prebuilt GitHub Release .deb package.

Release asset

cyphornips_1.5.0_amd64.deb

Download from GitHub

curl -LO https://github.com/CyphornIPS/cyphorn-engine/releases/download/v1.5.0/cyphornips_1.5.0_amd64.deb

Install

sudo apt install ./cyphornips_1.5.0_amd64.deb

If using dpkg and dependencies are missing:

sudo dpkg -i cyphornips_1.5.0_amd64.deb
sudo apt-get install -f -y

Verify

cyphorn-engine --version
cyphornctl --version

⚙️ Configuration

Fresh installation: the two critical values to set are wan_interface and lan_interface.

/etc/cyphornips/cyphornips.conf

wan_interface = wan0
lan_interface = lan0

rules_dir           = /etc/cyphornips/rules
domain_policy_file  = /etc/cyphornips/domain_policy.conf
country_policy_file = /etc/cyphornips/country-policy.conf

log_level = INFO

Replace wan0 and lan0 with the real interface names. The engine refuses to start when required interface values are empty.

domain_policy.conf

Classifies domains and applies scoped policies. It ships active but with no real blocking entries.

state active
enabled true

domain gambling-site.example gambling
policy gambling 192.168.1.0/24 BLOCK 50

Resolution uses specificity first: exact host, then CIDR subnet, then ANY/*. Priority breaks ties within the same specificity tier.

country-policy.conf

Country policy provides geo-fencing and ships without countries blocked by default.

drop inbound KP ANY

Syntax:

allow|alert|drop inbound|outbound ISO_CODE CIDR|ANY

Rules are evaluated top-to-bottom; the first matching rule wins.

categories.conf

This is an administrator bookkeeping/checklist file. The engine does not read it directly.

Rules layout

🏗️ Architecture & Data Pipeline

flowchart TD A[Ingress Packet WAN / LAN] --> B[eBPF TC Ingress Filter] B --> C[L2-L4 Decoders] C --> D[Conntrack & Flow Tracker] D --> E{Protocol DPI} E --> F1[HTTP] E --> F2[TLS / QUIC] E --> F3[DNS] E --> F4[FTP] E --> F5[SMTP / MIME] F1 --> G[File Extraction] F4 --> G G --> H[File Hashes] F1 --> I[Detection Engine] F2 --> I F3 --> I F4 --> I F5 --> I H --> I I --> J[Rules / Datasets / Flowbits] J --> K[Domain / Country Policy] K --> L{Action Precedence} L -->|PASS| M[Forward] L -->|DROP / REJECT| N[eBPF Policy Map] L -->|ALERT| O[Alert + Forward]

⚡ Packet I/O & eBPF / TC

Inline capture

Non-blocking raw packet sockets inspect traffic between dedicated interfaces.

Early enforcement

eBPF TC policy maps can drop traffic before the normal userspace/IP path.

Offload handling

The engine can disable GRO/offload behavior needed for predictable inspection.

Pre-forward synchronization

Userspace checks the same policy state before transmission.

🌐 HTTP

HTTP inspection exposes sticky buffers including http.uri, http.host, http.method, headers, cookies and request/response bodies.

🔐 TLS / JA3

TLS inspection extracts SNI, certificate fields, negotiated version and JA3 client fingerprints. JA3 logging is optional.

tls_log_ja3 = true

🔎 DNS

DNS wire inspection supports UDP and TCP queries and exposes dns.query for detection.

🚀 QUIC / HTTP/3

CyphornIPS can inspect QUIC Initial packets and recover TLS 1.3 ClientHello metadata such as SNI. Normal 1-RTT application data is not decrypted.

📁 FTP

FTP control/data tracking supports active/passive negotiation and file extraction from data transfers.

🧩 Detection Engine

Rules

Snort/Suricata-compatible grammar with content matching and protocol conditions.

Datasets

External feeds provide O(1) membership checks for large indicator sets.

Flowbits

Stateful correlation lets one rule mark a flow and another consume that state.

File Intelligence

Exact MD5, SHA-1, SHA-256 and SHA3-384 matching against a normalized dataset.

Canonical fingerprints

64-character SHA-256 canonical fingerprints identify normalized rules independently of SID alone.

Action precedence

flowchart LR A[Multiple matches] --> B{PASS?} B -->|Yes| C[PASS - Forward] B -->|No| D{DROP / REJECT?} D -->|Yes| E[BLOCK] D -->|No| F{ALERT?} F -->|Yes| G[ALERT + Forward] F -->|No| H[No match]

PASS > DROP/REJECT > ALERT

🔄 Update Engine

Updates can retrieve rule and File Intelligence artifacts from the CyphornIPS GitHub provider or a generic HTTP/S3/R2 endpoint.

flowchart LR A[Provider] --> B[Manifest] B --> C[Ed25519 Verification] C --> D[Version Gate] D --> E[Staging] E --> F[SHA-256 Verification] F --> G[Sandbox Validation] G --> H[Backup] H --> I[Atomic Install] I --> J[Hot Reload] J --> K{Success?} K -->|Yes| L[New Generation Live] K -->|No| M[Rollback]

Integrity

  • Ed25519 manifest verification
  • SHA-256 artifact verification
  • Invalid/unsigned manifests rejected by default
  • --allow-unsigned-manifest is for lab/test use

Rollback

A backup is created before managed content is replaced; failed validation/compilation/reload can trigger restoration.

Hot reload

cyphornctl reload rules
cyphornctl reload intelligence
cyphornctl reload domain-policy
cyphornctl reload country-policy
cyphornctl reload all

🔐 Security Hardening

  • Compiler hardening and PIE configuration.
  • Bounded capabilities for network/eBPF operation.
  • Ed25519 manifest and SHA-256 artifact verification.
  • Sandboxed validation before managed data becomes active.
  • Kernel eBPF verifier protections and bounded access.
  • IPv4 and IPv6 kernel policy maps for early drops.

⚠️ Known Limitations

  • No TLS MITM/decryption.
  • QUIC inspection is limited to Initial/ClientHello metadata.
  • Stateful tracking requires both directions to cross the same inline instance.
  • Dual-interface inline architecture; no built-in clustering.
  • SMB/NFS runtime extraction adapters are not available.
  • HTTP/2 binary multiplexed frame decoding is not included.

⚠️ Disclaimer

Developer Preview / Alpha: CyphornIPS v1.5.0 is provided for evaluation, security research, lab validation and community testing. It is not designed or certified as a sole, unmonitored security perimeter for mission-critical production.
  • False positives and false negatives are possible.
  • Stage new blocking rules as alert before promoting to drop/reject.
  • Broad DROP or PASS policies can cause operational impact.
  • CyphornIPS is defense-in-depth and does not replace hardening, patching, IAM/MFA, backups or incident response.
  • Administrators are responsible for applicable privacy and telecommunications compliance.
